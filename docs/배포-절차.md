# 배포 절차 — Oracle Cloud(Ampere A1, Ubuntu) + Docker Compose + Caddy

처음 서버를 올릴 때, 도메인을 붙일 때, 그 뒤 운영할 때 할 일을 순서대로 적었다. 명령은 서버의 기본 사용자(`ubuntu`) 기준이다. 요약판은 [README의 서버 배포](../README.md#서버-배포-오라클-클라우드-ubuntu)에 있다.

> **도메인을 붙이기 전(평문 HTTP)에는 관리자 페이지를 공개 IP로 열지 않는다.** 앱 포트(3000)는 서버 루프백에만 묶여 있으므로 내 PC에서 SSH 터널로 들어간다. 배포 이미지는 `ADMIN_TOTP_SECRET`이 없거나 `ADMIN_PASSWORD`가 10자 미만·예시 값이면 관리자 로그인을 거부한다(`src/lib/auth.ts`의 `productionLoginBlocker`, Dockerfile의 `APP_ENV=production`).

## 1. 처음 한 번

### 1-1. OCI 콘솔
1. Compute → 인스턴스 생성: Ubuntu 22.04 이상, Ampere A1(무료 티어 4 OCPU·24GB 범위 안), 공개 IP 할당, SSH 공개키 등록
2. Networking → VCN → 서브넷의 **보안 목록** → Ingress 규칙 추가: TCP **80**, TCP **443** (소스 `0.0.0.0/0`)
3. 인스턴스 상세에서 공개 IP를 적어 둔다

### 1-2. 서버 접속과 초기 설정
```bash
ssh ubuntu@<서버IP>
git clone https://github.com/vittroi384/qr-web.git ~/qr-web
bash ~/qr-web/scripts/server-setup.sh
```
스크립트가 하는 일: 인스턴스 방화벽(iptables)에 80/443 개방 → Docker 설치 → `.env` 생성(세션 키·관리자 입구 경로·DB 비밀번호·Umami 비밀값 자동 채움). 끝나면 **관리자 입구 경로(`ADMIN_PATH`)를 출력하니 북마크**한다.

### 1-3. `.env` 편집
```bash
cd ~/qr-web && nano .env
```
| 키 | 값 |
|---|---|
| `ADMIN_PASSWORD` | 10자 이상, 유일한 값. 예시 값(`change-me-…`, `admin1234` 등)은 거부됨 |
| `ADMIN_TOTP_SECRET` | 지금은 비워 두고 1-5에서 채움 |
| `DOMAIN` | DNS를 연결하기 전까지 비워 둠 |
| `ADMIN_ALLOWED_IPS` | 선택. 내 집·회사 IP/CIDR만 허용하려면 |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | 선택. 백업 결과 알림 |

### 1-4. 빌드·기동
```bash
newgrp docker        # 또는 로그아웃 후 재접속 (docker 그룹 반영)
./deploy.sh          # git pull(ff-only) → 비밀값 점검 → docker compose up -d --build
```
A1에서 첫 빌드는 몇 분 걸린다. 마이그레이션은 앱 컨테이너가 시작할 때 자동 적용된다(`docker compose logs app`에 `[migrate]` 줄).

### 1-5. OTP 등록 — 첫 로그인 전 필수
```bash
docker compose exec app node scripts/totp-setup.mjs   # 터미널에 QR이 뜬다 → Google Authenticator로 스캔
nano .env                                             # 출력된 ADMIN_TOTP_SECRET=… 추가
docker compose up -d                                  # 환경값 다시 읽기
```

### 1-6. 관리자 접속 (도메인 전)
내 PC에서 터널을 열고, 브라우저로 `http://localhost:3000/<ADMIN_PATH>`.
```bash
ssh -L 3000:127.0.0.1:3000 ubuntu@<서버IP>
```
로그인: 비밀번호 + 인증 앱의 6자리. 5회 실패 시 10분 잠금.

### 1-7. 관리자 설정 확인
- **사이트 URL**: 비어 있으면 `DOMAIN`에서 자동 생성되지만, 도메인 전에는 `http://<서버IP>`로 맞춰 둔다(sitemap·canonical에 쓰임)
- **개인정보 문의 연락처**: `jjook924@gmail.com`. 비어 있으면 대시보드에 경고가 뜨고 개인정보처리방침에 문의 문장이 빠진다
- 광고 자리표시(placeholder)는 레이아웃 확인이 끝나면 끈다

### 1-8. 일일 백업 cron
```bash
(crontab -l 2>/dev/null; echo "30 4 * * * $HOME/qr-web/scripts/backup.sh >> $HOME/qr-web/backups/backup.log 2>&1") | crontab -
```
`backups/qr-YYYY-MM-DD.sql.gz`(+ `umami-…`)를 30일 보관한다. 한 번은 복원까지 해 본다(아래 3절).

### 1-9. 같은 서버에서 80/443을 다른 프로젝트가 쓰고 있을 때
QR 앱을 다른 포트(기본 8080, 평문 HTTP)로 띄운다. `.env`에 두 줄을 추가하고 방화벽·보안 목록에 그 포트를 연다.
```bash
cat >> .env <<'EOF2'
COMPOSE_FILE=docker-compose.yml:docker-compose.port.yml
QR_HTTP_PORT=8080
EOF2
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 8080 -j ACCEPT && sudo netfilter-persistent save
./deploy.sh
```
OCI 콘솔 보안 목록에도 TCP 8080 Ingress를 추가한다. 접속은 `http://<서버IP>:8080`. 관리자는 1-6의 터널 방식 그대로(앱 포트 3000은 변함없음). 도메인을 붙일 때는 2절 대신 기존 프로젝트의 Caddy에 QR 블록을 추가해 443을 같이 쓴다(아래 2-B).

## 2. 도메인 연결할 때

1. 도메인 DNS에서 A 레코드를 서버 공개 IP로(루트와 `www` 둘 다 쓰려면 둘 다)
2. 서버에서 `.env`의 `DOMAIN=example.com`을 채우고 `docker compose up -d` → Caddy가 Let's Encrypt 인증서를 자동 발급(80/443이 열려 있어야 함)
3. 관리자 → 설정 → 사이트 URL을 `https://example.com`으로
4. 이후 관리자는 `https://example.com/<ADMIN_PATH>`로 직접 접속. 세션 쿠키에 `Secure`가 붙는다

### 2-B. 다른 프로젝트의 Caddy가 443을 쓰고 있을 때
QR 앱 컨테이너는 그대로 두고(앱은 `127.0.0.1:3000`, Umami는 `127.0.0.1:3001`에 묶여 있음) 기존 Caddy에 블록을 추가한다. 기존 Caddy가 컨테이너라면 그 compose의 caddy 서비스에 `extra_hosts: ["host.docker.internal:host-gateway"]`를 넣어야 호스트 포트에 닿는다.
```caddyfile
qr.example.com {
	encode zstd gzip
	handle /umami/script.js { rewrite * /script.js
		reverse_proxy host.docker.internal:3001 }
	handle /umami/api/send { rewrite * /api/send
		reverse_proxy host.docker.internal:3001 }
	reverse_proxy host.docker.internal:3000
}
```
QR 쪽 `.env`에는 `DOMAIN=qr.example.com`을 넣어 쿠키가 `Secure`로 발급되게 하고, `COMPOSE_FILE` 줄은 지우고 caddy 서비스는 띄우지 않는다(`docker compose up -d --scale caddy=0` 또는 compose에서 제외). 기존 Caddy의 TLS-ALPN 방식이면 80 없이도 인증서가 발급된다.
5. Umami: 관리자 → 설정 → 방문 분석에 스크립트 URL `https://example.com/umami/script.js`와 웹사이트 ID 입력(Umami 대시보드는 `ssh -L 3001:127.0.0.1:3001 ubuntu@<서버IP>` → `http://localhost:3001`, 기본 계정 admin/umami의 비밀번호를 첫 접속 때 바꾼다)
6. Search Console·AdSense 등록, README 상단에 라이브 URL 추가, Lighthouse 재측정

## 3. 운영

| 할 일 | 명령 |
|---|---|
| 코드 업데이트 | `cd ~/qr-web && ./deploy.sh` |
| 상태 | `docker compose ps` · `curl -s localhost/api/health` (DB 핑 포함, 200/503) |
| 앱 로그 | `docker compose logs -f app` — 한 줄 JSON: `admin.login`, `admin.login_failed`, `admin.login_locked`, `admin.login_refused_unsafe_config`, `log.rate_limited`, `retention.cleanup_failed` |
| Caddy 접근 로그 | `docker compose exec caddy cat /data/access.log` |
| 백업 복원 | `gunzip -c backups/qr-YYYY-MM-DD.sql.gz \| docker compose exec -T db psql -U qr -d qr` |
| 재시작 | `docker compose restart app` (설정값은 관리자 화면에서 바꾸면 재배포 없이 30초 안에 반영) |
| 디스크 정리 | `docker image prune -f` (옛 빌드 이미지) |

### 자주 막히는 곳
- **사이트가 안 열림**: OCI 보안 목록(80/443)과 인스턴스 iptables 둘 다 열려 있어야 한다. `sudo iptables -L INPUT -n | grep -E '80|443'`
- **HTTPS 발급 실패**: DNS가 아직 서버 IP를 가리키지 않거나 80이 막혀 있다. `docker compose logs caddy`
- **관리자 로그인이 503**: `.env`의 TOTP·비밀번호 조건 미충족. 메시지에 사유가 나온다. 고친 뒤 `docker compose up -d`
- **관리자 입구가 404**: 경로를 잘못 쳤거나 `ADMIN_ALLOWED_IPS`에 내 IP가 없다. 터널로 접속하면 서버 자신(루프백)으로 들어오므로 IP 목록에 `127.0.0.1`도 필요하다
- **E2E/로컬에서는 되는데 서버에서만 다르다**: 서버는 `APP_ENV=production` 이미지라 로그인 안전장치가 켜져 있다. 로컬 `next start`에는 없다
