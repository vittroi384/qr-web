# ADR-007: 방문 분석은 쿠키 없는 Umami를 자체 호스팅하고, 대시보드는 외부에 열지 않는다

- 상태: 채택 (2026-10-02)
- 결정자: 운영자

## 맥락

관리자 집계(저장 수)만으로는 "누가 어디서 들어와 어디서 포기하는지"를 알 수 없었다. 선택지는 Google Analytics(GA4), 호스팅형 Plausible/Umami, 자체 호스팅 Umami. 사이트는 독일어·프랑스어·스페인어 랜딩을 포함한 9개 언어로 유럽 트래픽을 받으므로, 쿠키 기반 분석은 동의 배너(CMP)를 요구하고, 그 배너는 도구형 사이트의 첫 화면 경험을 해친다. 또한 운영자는 다른 프로젝트들과 같은 서버에서 직접 운영하는 경험을 포트폴리오로 삼고 싶어 했다.

리뷰에서 추가로 드러난 사실: Umami는 기본 계정(admin/umami)으로 기동한다. `stats.<도메인>` 같은 서브도메인으로 공개하면 Caddy가 발급한 인증서가 Certificate Transparency 로그에 오르고, 이를 감시하는 스캐너가 수 분 안에 접근해 비밀번호를 먼저 바꿀 수 있다. "배포 직후 비밀번호를 바꾸라"는 문서 안내는 이 경쟁 조건을 막지 못한다.

## 결정

- **Umami를 같은 Docker Compose에 자체 호스팅**한다(고정 버전, 전용 PostgreSQL role과 DB `umami`, 텔레메트리 off).
- **대시보드는 외부에 노출하지 않는다.** 컨테이너 포트는 `127.0.0.1:3001`에만 바인딩하고, 운영자는 `ssh -L 3001:127.0.0.1:3001`로 접근한다. 별도 DNS·인증서가 없으므로 CT 로그에도 흔적이 없다.
- **공개 경로는 추적기 두 개뿐**: Caddy가 본 도메인 아래 `/umami/script.js`와 `/umami/api/send`만 Umami로 프록시하고, 그 외 `/umami/*`는 404.
- 스크립트 삽입은 관리자 설정(`analytics_script_url`·`analytics_website_id`)으로 켜고 끈다. URL은 **https + `.js` 경로만** 허용(관리자 세션이 탈취돼도 임의 스크립트 주입 범위를 좁힘), 관리자 페이지에는 삽입하지 않는다.
- 제품 내부 퍼널(선택 → 미리보기 → 저장)은 Umami와 별개로 **일·언어·종류·단계별 카운터만** DB에 둔다(IP·UA·내용 없음). 저장은 `/api/log`가 집계하므로 입력 기록과 항상 일치한다.
- `deploy.sh`가 Umami 시크릿·role·DB를 멱등하게 생성한다(기존 볼륨에서도 수동 SQL 불필요). 백업은 `qr`와 `umami` 두 DB를 모두 덤프한다.

## 결과

- 긍정: 동의 배너 없이 유럽 트래픽 분석 가능, 데이터가 운영자 DB에 남음, 월 비용 0. 관리자 통계 탭과 Umami를 합치면 "어느 언어·페이지에서 들어와 어디서 포기하고 무엇을 저장했는지"가 이어진다.
- 부정/트레이드오프: 대시보드를 보려면 SSH 터널을 열어야 한다(모바일에서 즉시 확인 불가). A1 서버의 메모리를 Umami 컨테이너가 수백 MB 더 쓴다. 퍼널 카운터는 클라이언트 세션 단위 중복 제거라 완벽히 정확하지는 않다(지표의 방향을 보는 용도).
- 거부한 대안: GA4(쿠키·동의 배너·데이터 외부 보관), 호스팅형 분석(유료 또는 데이터 외부 보관), Umami 서브도메인 공개 + basic auth(인증서 발급 자체가 존재를 알리고 비밀번호 관리가 하나 더 생김).
