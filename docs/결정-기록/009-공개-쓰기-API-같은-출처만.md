# ADR-009: 공개 쓰기 API는 이 사이트의 페이지에서 보낸 JSON 요청만 받고, 저장 행은 종류별 필드로 제한한다

- 상태: 채택
- 날짜: 2026-10-06
- 관련: [ADR-002](002-저장할-때만-기록.md), [ADR-004](004-저장-전-마스킹.md)

## 맥락

`/api/log`(저장 기록)와 `/api/funnel`(퍼널 카운터)은 로그인 없이 누구나 호출할 수 있는 쓰기 엔드포인트다. 공개 후 보안 점검에서 두 가지가 드러났다.

1. 다른 웹사이트가 자기 방문자의 브라우저로 `sendBeacon`을 쏘면, 그 방문자의 실제 IP로 가짜 기록이 쌓이고 퍼널 수치가 오염된다. IP당 요청 제한은 IP가 수천 개로 흩어지면 아무것도 막지 못한다.
2. payload의 키를 종류별로 제한하지 않아 요청 하나가 16KB까지 그대로 저장됐다. IP 하나로 하루 약 0.7GB, IPv6 /64를 바꿔 가며 쓰면 그 수십 배를 디스크에 쓸 수 있었다. Postgres를 Umami와 공유하므로 디스크가 차면 사이트 전체가 멈춘다.

## 결정

- 두 엔드포인트는 **Origin(없으면 Referer)의 호스트가 요청의 Host와 같고**, `Content-Type`이 `application/json`일 때만 처리한다. 아니면 본문을 읽기 전에 403/415로 끝낸다. 브라우저는 POST에 항상 Origin을 붙이므로 정상 저장은 영향이 없고, 다른 사이트에서 온 요청과 `Origin: null`은 걸러진다. 같은 출처 판정은 로그인 API가 이미 쓰던 헬퍼를 공유한다.
- 저장 행은 **그 QR 종류가 실제로 가진 필드만** 남긴다(일괄 생성은 `count·mode·sample` 추가). 문자 총량은 행당 3,000자(QR 한 장이 담을 수 있는 최대 2,953바이트에 맞춤). 옵션 키도 화이트리스트.
- IP당 제한(기록 30/분, 퍼널 60/분) 위에 **사이트 전체 상한**(기록 300/분, 퍼널 600/분)을 둔다. 전체 버킷은 본문 검증을 통과한 정상 행에만 차감해, 쓰레기 요청이 정상 방문자 몫을 쓰지 못하게 한다.

## 결과

- 좋은 점: 디스크 고갈과 타 사이트 위조가 막힌다. 정상 저장 경로(sendBeacon·keepalive fetch)는 E2E로 200을 확인했다.
- 대가: 전체 상한에 걸리면 정상 방문자의 기록도 버려진다(퍼널·기록 누락). 로그에 `log.rate_limited_site`로 남겨 추적할 수 있고, 트래픽이 늘면 상한을 올린다.
- 하지 않은 것: 전화·이메일·메시지 본문 등 나머지 필드의 평문 저장은 제품 정책으로 남겨 두었다(ADR-004는 Wi-Fi 비밀번호와 결제 식별자만). CSP는 AdSense 허용 목록 검증이 필요해 Report-Only부터 별도 작업으로 진행한다.
