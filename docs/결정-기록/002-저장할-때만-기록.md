# ADR-002: 방문자 입력은 저장 행동 시점에만 기록한다

- 상태: 채택 (2026-10-02) — 1차 구현(입력 1.5초 디바운스 자동 기록)과 2차(명시적 "생성" 버튼)를 거쳐 확정
- 결정자: 운영자

## 맥락

운영 관점에서 "누가 어떤 QR을 만들었는지"는 서버 DB에 남기고 싶었다. 1차 구현은 입력이 1.5초 멈출 때마다 전송했는데, 직접 써 보니 "타이핑할 때마다 저장되는" 느낌이 불쾌했고 미완성 입력이 기록에 쌓였다. "생성" 버튼을 두는 2차 구현은 실시간 미리보기의 장점을 죽였다.

## 결정

미리보기는 입력 즉시 브라우저에서 렌더하되 서버로는 아무것도 보내지 않는다. **PNG/SVG 다운로드, 클립보드 복사, 인쇄 안내판, 일괄 ZIP** — 사용자가 결과물을 가져가는 행동 — 에서만 `POST /api/log`로 1건을 기록한다. 이벤트 종류(`download_png`, `download_svg`, `copy`, `print`, `batch`)를 함께 저장해 "무엇으로 가져갔는지"만 구분한다.

## 결과

- 기록 1건 = 실제로 만들어진 QR 1개. 관리자 통계가 의미를 갖는다.
- 입력 도중 데이터는 서버에 도달하지 않으므로 개인정보 노출 면적이 줄어든다.
- 미리보기만 보고 떠난 방문자는 기록되지 않는다(의도된 손실).
- 일괄 생성은 전체 목록 대신 건수와 앞 3줄 샘플(200자)만 기록한다.
