# ADR-003: 관리자 영역은 존재 자체를 숨긴다

- 상태: 채택 (2026-10-02)
- 결정자: 운영자

## 맥락

관리자는 운영자 1명이다. 공개 사이트의 `/admin`에 로그인 폼이 노출되면 무차별 대입·취약점 스캐너의 상시 표적이 된다. 운영자의 요구는 "주소창으로는 아무도 못 들어오고 나만 들어갈 수 있게"였다.

## 결정

세 계층을 겹친다.

1. **비밀 입구 경로** `ADMIN_PATH`(예: `/gate-7f3a9c2e`). 이 경로를 열면 서명된 게이트 쿠키(30일)를 발급하고 로그인으로 보낸다. 게이트 쿠키가 없으면 `/admin/*`과 관리자 API는 **앱의 일반 404 페이지와 동일한 응답**을 돌려준다(페이지는 동일, 관리자 API는 본문 없는 404).
2. **비밀번호 + TOTP**(RFC 6238, 의존성 없이 구현, 코드 재사용 차단). 5회 실패 시 10분 잠금, 실패마다 지연, Origin 검사.
3. **IP 허용목록**(선택) — 지정 IP/CIDR 외에는 입구 경로조차 404.

세션은 HTTPS에서 `__Host-` 접두 쿠키, `SameSite=Strict`, User-Agent 바인딩, 24시간 만료. 관리자 응답에 `noindex`, robots.txt에 경로를 적지 않는다.

## 결과

- 공격 표면이 "비밀 경로를 알고, 비밀번호를 알고, OTP 기기를 가진" 사람으로 줄어든다.
- 운영자는 입구 URL을 북마크해야 한다(30일마다 한 번). 다른 기기에서는 입구부터 다시.
- 게이트 토큰과 세션 토큰은 서로 다른 키로 서명되어 상호 재사용이 불가능하다(리뷰에서 검증).
- `X-Real-IP`를 신뢰하므로 앱 포트는 리버스 프록시(Caddy) 뒤에만 두고 외부에 publish하지 않는다.
