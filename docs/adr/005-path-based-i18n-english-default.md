# ADR-005: 경로 기반 i18n, 영어 기본

- 상태: 채택 (2026-10-02) — 초기 `/`=한국어, `/en`=영어에서 뒤집음
- 결정자: 운영자

## 맥락

운영자는 한국어 사용자지만 QR 생성기의 검색 수요는 영어권이 압도적이다. 쿠키/Accept-Language 기반 언어 전환은 검색엔진이 언어별 페이지를 따로 색인하지 못한다.

## 결정

- URL 경로로 언어를 나눈다: `/`(영어, 기본), `/ko/...`(한국어). 관리자는 한국어 고정.
- `proxy.ts`가 경로를 보고 `x-locale` 요청 헤더를 설정하고(클라이언트가 보낸 값은 덮어씀), 루트 레이아웃이 `<html lang>`·헤더·푸터 언어를 정한다.
- 페이지 본문은 `components/pages/*`로 공유하고 `app/ko/*`는 얇은 래퍼. 모든 문구는 `lib/i18n/{en,ko}.ts` 사전(타입으로 누락 검출).
- 모든 페이지에 hreflang(en/ko/x-default=en), sitemap에 양쪽 URL. 이전 `/en/*`는 301.
- 타입별 랜딩 콘텐츠는 번역이 아니라 언어별로 따로 쓴다.

## 결과

- 검색엔진이 언어별로 독립 색인·랭킹한다. 영어 롱테일 키워드(`whatsapp qr code generator` 등)가 주 유입 경로가 된다.
- 사전 파일이 커지고(랜딩 포함 수천 줄) 문구 추가 시 두 언어를 모두 채워야 한다 — 타입 검사가 강제한다.
- 기본값(사이트명·설명·푸터)은 영어로 바뀌었고, 관리자 설정으로 덮어쓸 수 있다.
